# 07. Безопасность и приватность

## Что шифруется сквозным шифрованием (E2EE)

| Где | E2EE | Почему |
|---|---|---|
| Личные сообщения (1:1) | **Да**, всегда | Приватная переписка |
| Групповые ЛС | **Да**, всегда | То же |
| Приватные каналы сервера (по желанию, до ~100 участников) | **Да**, если включено | Для закрытых обсуждений: штаб клана, руководство |
| Приватные звонки | **Да** | Ключи из MLS-группы |
| Публичные каналы серверов | Нет (TLS при передаче + шифрование диска на усмотрение админа) | Иначе пропадут поиск, модерация, боты и история для новых участников |

Протокол — **MLS** (RFC 9420), реализация **openmls**. Свою криптографию не пишем.

### Устройства и ключи

- У каждого устройства своя пара ключей, и каждое устройство — отдельный участник MLS-группы.
- Новое устройство подтверждается со старого (QR-код или код подтверждения).
- **Фраза восстановления** для резервной копии ключей. Без неё при потере всех устройств история E2EE-чатов будет утеряна. Пользователь должен понимать это заранее.
- Проверка собеседника по «отпечатку» (safety number) доступна по желанию.

### Минимизация метаданных

- Вход **без номера телефона**, email необязателен.
- IP-адреса не хранятся дольше, чем нужно для rate limit и защиты от атак (настраивается админом).
- Нет аналитики и телеметрии по умолчанию. Только отчёты о сбоях, по согласию пользователя.

## Общая безопасность

- Пароли хешируются Argon2id. 2FA через TOTP, позже passkeys (WebAuthn).
- Короткоживущий access token плюс refresh token, привязанный к устройству. Список активных сессий с возможностью завершить любую.
- Права проверяются **на сервере** при каждой операции.
- Markdown рендерится в безопасный набор элементов. Сырого HTML нет.
- Загрузки: лимит размера, проверка типа, отдача через подписанные URL с `Content-Disposition` и правильным `Content-Type`.
- Rate limit на всё. Защита от спама приглашениями и массовой регистрации (инвайт-only режим для инстанса).
- Модерация: баны, кики, тайм-ауты, аудит-лог.
- Зависимости проверяются автоматически (`cargo audit`, `npm audit`) в CI.

## Юридические вопросы (важно)

- **Self-hosted модель:** оператором является тот, кто поднял инстанс, а не мы как разработчики ПО. Это нужно чётко прописать в лицензии и документации.
- **Россия:** публичный сервис обмена сообщениями обязан состоять в реестре организаторов распространения информации (ОРИ), хранить переписку и передавать её по запросу (закон Яровой, СОРМ). E2EE с этим несовместимо.
  - **Нельзя запускать публичный инстанс для всех желающих без консультации юриста.**
  - Как ПО для частных и корпоративных инсталляций проект находится в другом положении, но и это нужно подтвердить у юриста.
- Персональные данные: 152-ФЗ и GDPR (для пользователей из ЕС). Нужны удаление аккаунта, экспорт данных и политика конфиденциальности как шаблон для админов инстансов.
