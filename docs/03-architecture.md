# 03. Архитектура и стек

## Схема (режим одного сервера, self-hosted)

```
  Десктоп-клиент (Slint)                         Веб-клиент (позже)
  ┌───────────────────────────────┐              ┌────────────────────┐
  │ UI: Slint (нативный)          │              │ UI: SolidJS        │
  │        ▲ вызовы Rust          │              │ голос: livekit-js  │
  │ Rust-ядро: сеть, SQLite-кэш,  │              └─────────┬──────────┘
  │ крипто (MLS), голос (LiveKit) │                        │
  └───────┬───────────┬───────────┘                        │
          │ HTTPS/WSS │ WebRTC (UDP)                       │
          ▼           ▼                                    ▼
  ┌─────────────────────────────┐      ┌──────────────────────────────┐
  │ feather-server (Rust, axum) │      │ LiveKit server (SFU + TURN)  │
  │  • REST API                 │─────►│  выдаём токены доступа       │
  │  • Gateway (WebSocket)      │      └──────────────────────────────┘
  │  • шина событий в процессе  │
  │  • обработка медиа (превью) │
  └──────┬──────────────┬───────┘
         ▼              ▼
   ┌──────────┐   ┌───────────────────────┐
   │ Postgres │   │ Файлы: диск или S3    │
   └──────────┘   └───────────────────────┘
```

Минимальная инсталляция — это **3 контейнера**: `feather-server`, `postgres` и `livekit`.

## Стек и почему он такой

| Часть | Выбор | Почему |
|---|---|---|
| Сервер | **Rust**: axum, tokio, sqlx | Мало памяти на сервере (важно для self-hosted на дешёвом VPS), общие крейты с клиентом (протокол, крипто) |
| БД | **PostgreSQL** | Надёжно, есть полнотекстовый поиск, хватит надолго |
| Шина событий | **В процессе** (tokio broadcast) | Для одного сервера Redis не нужен, проще установка |
| Шина для кластера | NATS (позже) | Подключается, только если нужен больше чем один инстанс |
| Файлы | Локальный диск, опционально S3 | Self-hosted без лишних сервисов |
| Голос и видео | **LiveKit** (self-hosted) | Готовый SFU, встроенный TURN, поддержка E2EE, Rust SDK для клиента |
| Десктоп и UI | **Slint** (нативный, Rust) | 20–75 МБ RAM против 244 МБ у Tauri, см. D12 и [bench](../bench/README.md) |
| Клиентское ядро | **Rust** | Сеть, кэш (SQLite), MLS (openmls), голос (livekit Rust SDK) |
| Веб-клиент | Отдельно, позже (открытый вопрос) | UI больше не общий с десктопом |
| Мобильные | Позже | Варианты: Tauri mobile или нативные приложения |

Альтернатива для сервера — Go: он проще в разработке. Rust выбран ради общего кода с клиентом. Если скорость разработки станет проблемой, решение можно пересмотреть до начала этапа 1.

## Структура репозитория (план)

```
feather/
├── docs/                 # эта документация
├── crates/
│   ├── protocol/         # типы API и событий Gateway, сериализация (сервер + клиент)
│   └── crypto/           # обёртка над openmls для E2EE
├── server/               # feather-server (axum)
├── client/
│   ├── core/             # Rust-ядро клиента: сеть, кэш, крипто, голос
│   ├── native/           # десктоп-клиент на Slint
│   ├── desktop/, ui/     # прототип на Tauri + SolidJS (для сравнения, удалить после этапа 0)
├── deploy/
│   ├── docker-compose.yml
│   └── livekit.yaml
└── bench/                # бенчмарки ресурсов клиента
```

## Подключение к нескольким серверам

Один клиент может быть подключён к нескольким инстансам одновременно (в списке слева, как серверы в Discord, только каждый — отдельный инстанс). У каждого инстанса свой аккаунт. Как сделать единый аккаунт для всех, пока открытый вопрос, см. [09-decisions](09-decisions.md).

## Режимы развёртывания

| Режим | Для кого | Состав |
|---|---|---|
| **Single-node** | 99 % инсталляций, до нескольких тысяч онлайн | server + postgres + livekit |
| Cluster | Большие сообщества | N × server + NATS + Postgres-реплики + несколько узлов LiveKit |
