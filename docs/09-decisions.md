# 09. Решения и открытые вопросы

## Принятые решения

| № | Дата | Решение | Причина |
|---|---|---|---|
| D1 | 2026-10-10 | Продукт self-hosted (направление 1) | Свобода от блокировок и чужих облаков, свободная ниша: удобство Discord, но на своём сервере |
| D2 | 2026-10-10 | E2EE частично: ЛС, группы, приватные каналы и звонки (направление 2) | Полное E2EE ломает поиск, модерацию и ботов в публичных каналах |
| D3 | 2026-10-10 | Основная аудитория — геймеры (направление 3) | Высокие требования к голосу и ресурсам, это наше главное преимущество |
| D4 | 2026-10-10 | Направление 5 (SDK) отложено, но протокол и ядро клиента — отдельные библиотеки | Сохраняем возможность без лишних затрат сейчас |
| D5 | 2026-10-10 | Бюджет ресурсов клиента — жёсткое требование с проверкой в CI | Ключевое отличие от Discord |
| D6 | 2026-10-10 | ~~Tauri v2 + SolidJS~~ **Отменено решением D12** | Замер: WebKitGTK занимает ~209 МБ даже на пустой странице |
| D7 | 2026-10-10 | Сервер на Rust (axum), PostgreSQL, шина событий в процессе | Мало ресурсов на сервере, общий код с клиентом, простая установка |
| D8 | 2026-10-10 | Голос через LiveKit (self-hosted) + Rust SDK в клиенте | Готовый SFU с TURN и E2EE, свой SFU — это месяцы работы |
| D9 | 2026-10-10 | E2EE на MLS (openmls) | Стандарт, подходит для групп, свою криптографию не пишем |
| D10 | 2026-10-10 | Главный ориентир — Discord. TeamSpeak и Mumble не считаем конкурентами | У них неудобное управление и интерфейс |
| D12 | 2026-10-10 | **Интерфейс десктопа на Slint (нативный, Rust)** вместо Tauri | Замер этапа 0: 20–75 МБ против 244 МБ у Tauri и 871 МБ у Discord, CPU при прокрутке 22 % против 49 %, внешний вид тот же ([bench/README.md](../bench/README.md)) |
| D13 | 2026-10-10 | Рендерер Slint по умолчанию GPU (femtovg), программный — «экономный режим» в настройках | На 2560×1440 программный тратит 43 % CPU при прокрутке против 27 % у GPU |
| D14 | 2026-10-10 | Демонстрация экрана только с аппаратным кодированием (NVENC → VA-API → …). Без него лимит 720p30 и предупреждение | Программное кодирование 1080p60: 80 % CPU и 9 fps, NVENC: 10–12 % и 60 fps |
| D15 | 2026-10-10 | Push-to-talk на Wayland через XDG-портал GlobalShortcuts | Единственный штатный способ ловить клавиши поверх игры без root и без чтения /dev/input |
| D16 | 2026-10-10 | Сессии — непрозрачные токены (32 случайных байта, в БД только SHA-256) вместо JWT | Мгновенный отзыв при выходе, утечка БД не даёт рабочих токенов, нет криптографии подписей. Цена — запрос к БД на каждый вызов (индекс по хешу; при нагрузке добавим кэш) |
| D17 | 2026-10-10 | Свой аудиотракт: захват/воспроизведение сами, шумодав RNNoise перед кодировщиком, `NativeAudioSource` вместо `PlatformAudio` | Шумодав WebRTC на уличном шуме почти не слышен (оценка пользователя), RNNoise −16,5 дБ фона при 1 % CPU; в PlatformAudio свою обработку не вставить и NS не выключить; заодно исправляется выбор устройства на Linux |
| D11 | 2026-10-10 | Этапы 0–1 разрабатываем локально, с этапа 2 один VPS для тестов через интернет | См. [10-test-infra](10-test-infra.md) |

## Открытые вопросы

- [x] ~~UI-технология~~ → решено: Slint (D12).
- [ ] **Веб-клиент.** UI больше не общий с десктопом. Делать отдельно (позже) или не делать?
- [ ] **Название.** «Feather» рабочее. Нужно проверить, что имя и домен свободны.
- [ ] **Лицензия.** Варианты: AGPL для сервера и MIT/Apache для протокола и SDK, или всё под AGPL. Влияет на возможное направление 5.
- [ ] **Аккаунты между инстансами.** Отдельный аккаунт на каждом сервере (просто) или единая идентичность (сложнее, ближе к федерации)?
- [ ] **Федерация.** Нужна ли вообще? Если да, то свой протокол или совместимость с Matrix?
- [ ] **Мобильные клиенты.** Tauri mobile или нативные (Kotlin/Swift)? Решаем после беты.
- [ ] **Монетизация.** Бесплатный open source плюс платный хостинг «под ключ», поддержка для компаний или SDK (направление 5)?
- [ ] **Юридическая консультация** по запуску в РФ (см. [07](07-security-privacy.md)).
