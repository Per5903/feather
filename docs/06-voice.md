# 06. Голос, видео, демонстрация экрана

Голос — главная функция для геймеров. По качеству и задержке он должен быть **не хуже Discord**.

## Схема

1. Клиент просит войти в голосовой канал: `POST /channels/{id}/voice/join`.
2. Сервер проверяет права (`CONNECT`, `SPEAK`) и выдаёт LiveKit-токен на комнату `voice:{channel_id}`.
3. Rust-ядро клиента подключается к LiveKit через **LiveKit Rust SDK** (нативный libwebrtc, а не WebView).
4. Сервер рассылает `VOICE_STATE_UPDATE` (кто в канале, mute и deafen) через Gateway.

Голосовой трафик не проходит через `feather-server`, он идёт напрямую между клиентом и LiveKit.

## Параметры звука

| Параметр | Значение |
|---|---|
| Кодек | Opus, 48 кГц |
| Битрейт | 32–64 кбит/с по умолчанию, до 128 кбит/с в настройках канала |
| DTX | Включён (в тишине почти нет трафика и нагрузки) |
| FEC | Включён (устойчивость к потерям пакетов) |
| Шумодав | RNNoise по умолчанию. Тяжёлый ML-шумодав доступен только как опция |
| Эхо и АРУ | Аудиопроцессор libwebrtc (AEC3, AGC) |
| Цель по задержке | Рот → ухо < 150 мс внутри региона |

## Функции для геймеров

- **Глобальный push-to-talk** работает, даже когда на переднем плане игра (системный хоткей из Rust-ядра).
- Активация голосом с настраиваемым порогом и индикатором уровня.
- Громкость каждого участника отдельно и локальный mute.
- Звуки входа и выхода из канала (можно отключить).
- Приоритетный говорящий (для командира рейда или капитана команды).
- Оверлей поверх игры, показывающий, кто говорит, появится позже, на этапе 4. Это отдельный лёгкий процесс, который можно выключить.

## Демонстрация экрана и видео

- Захват экрана: Windows Graphics Capture или DXGI на Windows, PipeWire через xdg-desktop-portal на Linux, ScreenCaptureKit на macOS.
- **Кодирование только аппаратное:** NVENC, QuickSync, AMF или VideoToolbox. Программное кодирование включается только как запасной вариант с предупреждением.
- Кодеки: H.264 (совместимость) и AV1 там, где есть аппаратная поддержка.
- Simulcast: зритель получает качество под свою сеть.

## E2EE в звонках

- Приватные звонки (ЛС, группы, E2EE-каналы) шифруются по кадрам через механизм E2EE LiveKit. Ключи распределяются через MLS-группу канала (см. [07](07-security-privacy.md)).
- Публичные голосовые каналы серверов идут без E2EE, но с транспортным шифрованием (DTLS-SRTP).

## Риски (проверить на прототипе этапа 0)

- [x] Аппаратное кодирование в SDK: NVENC 1080p60 при 10–12 % CPU, VA-API работает, программное непригодно (80 %, 9 fps) ([bench](../bench/README.md), замер 8)
- [ ] Настоящий захват экрана через портал PipeWire (нужен выбор экрана пользователем), путь DMA-BUF
- [ ] Захват на Windows
- [ ] E2EE в Rust SDK совместимо с веб-клиентом
- [ ] Глобальные хоткеи на Wayland: прототип `client/ptt-proto` через портал GlobalShortcuts (KDE 6.7, v2) доходит до диалога назначения клавиши, нужна проверка с пользователем. Хост-приложению нужен `.desktop`-файл с app id
- [x] Задержка тракта кодирование → сервер → декодирование: **39 мс** ([bench](../bench/README.md))
- [ ] Реальная нагрузка CPU в голосе укладывается в < 2 %. **Сейчас 8–9 %**, почти всё уходит на Opus и аудиоустройство libwebrtc, план оптимизации в [bench](../bench/README.md)
- [x] Реальные микрофон и динамики через `livekit::PlatformAudio`: работает, шумодав убирает ~20 дБ шума ([bench](../bench/README.md))
- [ ] Выбор устройства на Linux: PipeWire перебивает выбор (stream-restore), нужно своё `application.name` и проверка
- [ ] Режим «без обработки» (музыка/стрим): в SDK 0.9.4 программный шумодав не отключается
- [ ] Шумодав на слух, живым голосом
